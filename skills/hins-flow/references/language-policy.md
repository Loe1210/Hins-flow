# 用户可见内容语言规则

Hins-flow 默认面向中文用户。除非用户明确要求其他语言，否则所有需要用户阅读、确认、审查或长期维护的内容都使用简体中文。

## 必须使用简体中文

- 对用户的提问、选项、进度说明、Gate 说明、风险提示和最终总结；
- change note 的标题、Markdown 标题、正文、检查清单和审查记录；
- 需求规格、PRD、用户故事、验收标准、任务票和 handoff；
- `AGENTS.md` 中新增的说明、`CONTEXT.md`、`CONTEXT-MAP.md`、ADR 和 `docs/agents/*.md`；
- 计划审查、Standards/Spec 代码审查、缺陷说明和修复说明；
- issue、PR、提交信息、发布说明以及本流程新建或修改的其他说明文档；
- 对测试结果、构建结果、环境限制和原始错误的解释。

调用内置能力协议或审查执行单元时，在任务上下文中明确要求使用简体中文。上游协议可以保留英文作为机器内部参考，但不得把其中的英文提示、模板标题或阶段名直接暴露给用户；展示或写入用户可见文档前，必须转换成准确、自然的简体中文，并保留原有语义。

## 可以保留英文或原文

- YAML/JSON/TOML 等机器读取的键名、schema 字段和固定枚举值；
- 代码标识符、API 名称、类型名、包名、依赖名、文件名和路径；
- shell 命令、参数、环境变量、Git ref、slug 和状态机值；
- 原始测试输出、编译器输出、堆栈、日志和第三方错误消息；
- 必须逐字保留的外部协议、配置片段和引用。

保留原文后，紧接着用简体中文说明它的含义、影响和下一步。不要为了中文化而翻译代码、命令、路径、固定枚举或公共 API。

## 冲突处理

用户在当前任务中明确指定语言时，以用户要求为准。外部平台或仓库规范强制要求非中文格式时，保留所需格式，同时给用户提供完整的中文摘要。不得仅因为仓库现有文档是英文，就自行把本次用户可见内容切换成英文。
